03 家庭信息域全景 Information Domains

本文是需求的核心。 它回答"一个家庭到底有多少类信息值得管"。

你原始想法覆盖了 D01 人员基础信息 / D02 工作信息 / D03 健康管理 三项。下面扩展成 15 个域 / 107 个子域， 其中标注 ★新增 的是你未提及、但按家庭管理的完整度必须考虑的。标注 ★强推 的是我认为不该砍的。

优先级：P0 = v1 必做 / P1 = v1.1~v2 / P2 = 远期或按需。 优先级定义与 v1 边界见 08-scope-and-phasing.md。

D01 家庭与成员 ★强推

所有其它域都挂在"成员"或"家庭"上。这个域做不好，其它域全是散的。

# 子域 内容 核心字段示例 优先级
01 家庭档案 家庭本体信息 家庭名称、头像、创建时间、邀请码、时区、地区、币种、单位制、语言 P0
02 成员基础信息 人的基本属性 姓名、称谓（爸/妈/老大）、昵称、性别、出生日期、农历生日、头像 P0
03 成员可变属性 随时间变化的身体/偏好数据 身高、体重、鞋码、上衣/裤装尺码、腰围、眼镜度数、血型、过敏源 P1
04 家庭关系 成员间的结构与称谓 与管理员关系（本人/配偶/子女/父母/其他）、是否同住、排序 P0
05 成员角色与登录态 谁能登录、谁是管理员 角色、是否可登录、账号绑定、状态（正常/停用） P0
06 成员生命周期 人进人出 邀请、加入、停用、退出、数据移交（管理员变更） P0
07 证件档案 各类证照 证件类型、号码（加密）、签发机关、签发日、到期日、扫描件 P1
08 联系方式 怎么找到人 手机、邮箱、住址、单位地址、紧急联系人 P0

关键设计点

  • 一个账号 vs 一个成员：幼儿和部分长辈无账号（非登录成员），但仍是完整档案主体，且其数据由管理员代管。数据模型必须支持"成员 ≠ 账号"。
  • 农历：生日与纪念日需支持农历，否则长辈生日会记错。
  • 证件到期：是 D11 提醒功能的数据源，不单独做提醒。
  • 敏感字段加密：证件号属敏感个人信息，需字段级加密 + 访问审计。

D02 工作与职业（你已想到）

# 子域 内容 核心字段示例 优先级
01 任职信息 当前/历史任职 单位、部门、职位、职级、入职日期、工龄、是否在职 P0
02 薪酬结构 收入构成 基本工资、绩效、奖金、补贴、税前/税后、发薪日 P0
03 社保公积金 五险一金 缴纳基数、比例、公司/个人部分、账户余额、缴纳城市 P1
04 假勤管理 假期额度 年假总额/已用/剩余、调休、病假、加班记录 P1
05 职业发展 能力资产 技能标签、职称、职业证书（含有效期）、培训记录、绩效评价 P1
06 履历 过往经历 单位、职位、起止时间、离职原因 P2
07 副业/自由职业 非全职收入 项目名、客户、周期、收入、结算状态 P2
08 求职管理 找工作过程 目标岗位、简历版本、投递记录、面试记录、Offer P2
09 工作日程 排班与出差 班次、值班表、出差计划（与 D07 打通） P1

关键设计点

  • 薪酬是高敏感数据：默认仅本人 + 管理员可见，且大屏永不展示。
  • 社保公积金与 D04 财务重叠 → 口径要统一：缴纳记录归 D02，资金账户余额归 D04，不重复录入（见 Q-008）。

D03 健康与医疗（你已想到，价值最高）

# 子域 内容 核心字段示例 优先级
01 体检记录 定期体检 机构、日期、套餐、报告附件、结论、异常项 P0
02 指标记录 可量化序列 指标名、数值、单位、参考区间、测量时间 P0
03 指标字典 指标定义 指标名、单位、参考区间、适用人群、是否内置 P0
04 慢病管理 长期疾病 疾病名称、确诊日期、分期分级、控制目标、随访周期 P1
05 用药记录 服药管理 药品名、规格、剂量、频次、途径、起止日期、开方医院、剩余量 P0
06 用药提醒与打卡 实际执行 提醒时间、是否已服、漏服记录 P1
07 疫苗接种 接种史 疫苗名、剂次、接种日期、机构、下次时间 P1
08 过敏与病史 风险信息 过敏源（药物/食物/环境）、既往史、手术史、家族史 P0
09 就诊记录 看病过程 医院、科室、医生、主诉、诊断、处方、费用、单据 P0
10 医疗单据与报销 费用凭证 发票、费用明细、医保报销金额、自付金额 P1
11 专科档案 分科记录 视力（验光）、牙齿、心理评估、听力 P2
12 运动与睡眠 生活方式 运动类型/时长/消耗、步数、睡眠时长与质量 P2
13 儿童健康 成长轨迹 生长曲线（身高/体重/头围）、发育里程碑 P1
14 女性健康 专项 经期记录、孕期检查 P2

关键设计点

  • 指标字典必须可自定义（子域 03）。不同家庭的关注指标不同，硬编码必然不够用。内置一套常用指标 + 允许家庭自定义，是P0 设计约束。
  • 指标序列 = 时间序列：血压/体重这类数据要能做趋势图，因此存储需支持"同一指标多点、可聚合"。
  • 报告是附件不是文本：体检报告基本是 PDF/图片，靠 OCR 提取全部指标不可靠。v1 策略应是"附件 + 手工录入关键几项"，而不是"全自动识别"。OCR 全量结构化列为 P2。
  • 不做诊断结论：系统只做记录、对比、提醒"指标超出参考区间"，绝不给医学建议。
  • 与 D09（长辈照护）、D08（儿童）共用本域的表，不重复建表。

D04 财务与资产 ★强推（你未提及，但家庭最刚性）

# 子域 内容 核心字段示例 优先级
01 账户管理 资金账户 账户类型、名称、机构、卡号后四位、币种、是否共享 P0
02 收支记账 流水 日期、金额、方向、分类、成员、账户、商家、备注、附件、标签 P0
03 分类管理 收支科目 一级/二级分类、类型（收入/支出/转账）、排序 P0
04 预算管理 预算与预警 周期、总预算、分项预算、已用、预警阈值 P1
05 资产负债快照 净值 快照日期、总资产、总负债、净值 P1
06 负债管理 贷款 类型、债权方、本金、利率、剩余期数、还款日、月供 P0
07 账单与订阅 固定扣费 名称、金额、周期、扣款日、到期日、自动续费开关 P0
08 保险管理 保单 公司、险种、保单号、投保人/被保人/受益人、保额、保费、缴费期、保障期 P1
09 投资持仓 资产明细 标的、成本、份额、账户、备注（不做行情、不做建议） P2
10 财务目标 攒钱计划 目标名称、目标金额、当前进度、截止日期、关联账户 P2

关键设计点

  • 本域是全项目最高敏感级别。必须支持"某成员对某账户/某笔记录完全不可见"。
  • 不做银行/支付账单自动导入（v1）。支付宝/微信账单导入需解析非标准导出文件且易失效，成本高、稳定性差 → 建议 v1 做 Excel/CSV 手工导入，自动对接列 P2。
  • 记账的关键是"记起来不费劲"，而不是功能全。v1 应该优先做"3 秒记一笔"，而不是预算图表。
  • 与 D02（薪酬）、D05（房贷车贷）、D06（水电费）、D08（学费）有交叉 → 强调"一次录入、多处引用"，禁止重复录入。

D05 房产与车辆 ★新增

# 子域 内容 核心字段示例 优先级
01 房产档案 房子 地址、面积、户型、产权人、产权证、购入日期/价格、当前估值 P1
02 房产贷款与出租 相关财务 贷款信息、月供、租客信息、租金、租期起止 P1
03 车辆档案 车 车牌、品牌型号、VIN、购入日期、里程、颜色 P1
04 车辆事务 用车成本与合规 交强险/商业险到期、年检到期、保养记录、维修记录、违章、油耗 P1

关键设计点

  • 车辆"三到期"（保险、年检、保养）是强提醒场景，与 D11 联动。
  • 油价波动导致的成本统计价值有限，v1 只做记录不做分析。

D06 家居与设备 ★新增

# 子域 内容 核心字段示例 优先级
01 家电设备 大件电器 名称、品牌型号、购入日期、价格、渠道、保修到期、说明书/发票附件 P1
02 维修记录 维修历史 设备、故障、维修方、费用、日期、结果 P1
03 家具与贵重物品 财物清单 名称、估值、图片、存放位置 P2
04 日用品库存 消耗品 物品、数量、最低库存、存放位置 P2
05 家庭药箱 药品库存 药品名、数量、有效期、存放位置 P1
06 固定费用缴纳 户号与账单 水电燃气/宽带/物业/取暖的户号、缴费周期、绑定自动扣费 P1

关键设计点

  • "保修到期"和"药箱有效期"是两个容易被忽视但极实用的提醒。买了三年才想起来保修过期是常见痛点。
  • 家庭药箱与 D03 用药记录联动：药箱 → 用药时自动带出药品信息并扣减数量。

D07 日历与日程 ★强推（大屏的燃料）

# 子域 内容 核心字段示例 优先级
01 家庭共享日历 全家可见的事件 标题、时间、地点、参与成员、备注、提醒 P0
02 个人日程 私人事件 同上 + 可见性 P0
03 纪念日 固定日期 类型（生日/结婚纪念/忌日/节日）、公历/农历、是否每年重复、提前提醒天数 P0
04 待办事项 任务 标题、负责人、截止日、优先级、状态、重复规则、清单归属 P0
05 家务分工 轮值 家务项、轮值规则（轮换/固定）、执行人、完成打卡、积分 P1
06 家庭会议 记录 日期、议题、决议、待跟进事项 P2
07 到期提醒中心 聚合提醒 来源（各域的到期项）、提前量、通知渠道、已读状态 P0

关键设计点

  • 子域 07 是横向能力，不是独立功能：D01 证件、D04 还款日、D05 车检、D06 保修、D03 用药/复诊 —— 全部汇聚到统一提醒中心。若每个域各做一套提醒，必然重复且体验割裂。
  • 农历支持是硬需求（长辈生日、忌日）。
  • 日历对外订阅（iCal 导出）列 P1，能让大屏和手机系统日历互通。

D08 子女与教育 ★新增

# 子域 内容 核心字段示例 优先级
01 学校信息 在读学校 学校、年级、班级、班主任、联系方式、学号 P1
02 课表 作息 周课表、上下学时间、延时服务 P1
03 成绩记录 学业表现 考试名、日期、科目、分数、满分、班级排名、年级排名 P1
04 作业与任务 家校协同 科目、内容、截止、完成状态 P2
05 兴趣班/培训 课外班 机构、老师、课时总额/已用/剩余、单课时价、上课时间 P1
06 成长记录 里程碑 身高体重曲线、第一次里程碑、照片 P1
07 素质档案 证书与作品 获奖记录、考级证书、作品集 P2
08 教育支出 费用汇总 学费、培训费、书本费（汇总到 D04） P2

关键设计点

  • "课时余额"是真实痛点：培训班买了 100 课时，上到第几十节就记不清了。这是本域最有实用价值的点，值得优先做。
  • 未成年人数据属敏感个人信息，采集范围应最小化，且需监护人同意（PIPL 要求）。

D09 长辈照护 ★新增

# 子域 内容 核心字段示例 优先级
01 照护档案 长辈专项 行动能力、认知状态、是否需要陪护、护理等级 P1
02 照护安排 排班 陪护人、值班表、探访记录 P1
03 用药与监测打卡 执行记录 服药打卡、血压血糖记录（复用 D03） P1
04 医疗资源 常用信息 常去医院、主治医生、医保信息、护理机构 P1
05 养老规划 长期安排 养老保险、机构意向、资金准备（关联 D04） P2

关键设计点

  • 复用 D03 而非新建：长辈的健康数据就是 D03 的数据，本域只加"照护"特有的部分。
  • 打卡类功能需要极简交互（一个大按钮），且要考虑长辈本人操作或他人代打。

D10 关系与人情 ★新增（中国特色刚需）

# 子域 内容 核心字段示例 优先级
01 亲属关系图谱 家族结构 称谓、关系、分支（父系/母系）、生卒 P1
02 亲友通讯录 人脉 姓名、关系、生日（农历/公历）、联系方式、备注 P1
03 人情往来 随礼记账 事由（婚/丧/满月/升学/乔迁）、对象、金额、日期、场合 P1
04 社交分组 分类 同事、同学、邻居、亲戚 P2

关键设计点

  • "还礼提醒"是这个域的杀手锏：谁在什么时候给了多少，下次对方有事该还多少 —— 传统上靠记忆或纸质本子，非常容易出错。做得好的话，这一项就足以让家人愿意用这个系统。
  • 本域数据相对不敏感，适合放上大屏（如"本月生日提醒"）。

D11 生活事务与行政 ★强推

# 子域 内容 核心字段示例 优先级
01 证件到期管理 有效期追踪 证件、到期日、提前提醒天数、续办状态 P0
02 签证与出入境 涉外事务 签证类型、有效期、出入境记录 P2
03 会员与订阅 花在订阅上的钱 平台、金额、周期、到期日、自动续费 P1
04 宠物档案 宠物 品种、生日、疫苗、驱虫、体重、就诊记录 P2
05 家庭日记 生活记录 日期、内容、图片、参与人 P2

关键设计点

  • 证件到期是全项目"投入产出比"最高的功能之一：数据量极小（几条就够），但一次提醒可能省掉巨大麻烦（护照过期误机、驾照过期被查）。
  • 会员订阅与 D04 账单订阅存在重叠 → 需统一（见 Q-008）。

D12 旅行与出行 ★新增

# 子域 内容 核心字段示例 优先级
01 行程计划 计划 目的地、起止日期、参与人、预算、行程单 P2
02 交通订单 票务 类型、班次、时间、座位、订单号、价格 P2
03 住宿订单 酒店 酒店、地址、入住/退房、房型、订单号 P2
04 行李清单 模板化清单 按目的地/季节/人群的模板 P2
05 旅行证件与保险 出行合规 护照签证要求、旅行保险单 P2
06 旅行记录 复盘 花费汇总、照片、评分、攻略笔记 P2

关键设计点：整体列 P2，但"行李清单模板"是低成本高体验的小功能，可单独提前。

D13 文档与知识库 ★强推（基础设施）

这是所有域的附件能力，不是可选功能。体检报告、保单、发票、说明书都要放这里。

# 子域 内容 核心字段示例 优先级
01 家庭文件库 附件存储 文件、类型、标签、归属（成员/域/对象）、上传人、上传时间 P0
02 重要信息保管 强敏感 WiFi 密码、门锁密码、保险箱位置、账户信息（强加密 + 访问审计） P1
03 应急手册 突发应对 急救信息、常去医院与路线、紧急联系人、家庭 SOP P1
04 家谱与纪念 长期传承 家族故事、老照片、口述史 P2

关键设计点

  • 子域 02 是炸弹：存密码类信息必须在功能设计阶段明确"加密方案 + 谁能看 + 有没有留痕"。若无把握，建议 v1 不做，引导用户用专业密码管理器。
  • 附件需考虑存储成本（对象存储）与生命周期（照片类可降级存储）。
  • 家谱/老照片是"十年后才体现价值"的功能，但正因如此，越早开始沉淀越好 —— 属于 P2 但值得留位置。

D14 大屏与展示（你的核心诉求）

详细需求见 06-dashboard-requirements.md。

# 子域 内容 优先级
01 大屏设备管理 设备注册、配对码授权、在线状态、绑定家庭 P0
02 布局定制 栅格布局、卡片增删/拖拽/缩放/换位、多套布局保存 P0
03 卡片库 预置卡片集合（日历/天气/待办/生日倒计时/相册/健康概览/财务概览/家务轮值/留言板/时钟/快递等） P0
04 场景切换 布局+主题+数据范围的组合（日常/节日/来客） P1
05 展示策略 刷新频率、轮播、夜间调暗/熄屏、防烧屏像素偏移 P0
06 隐私脱敏 敏感卡片默认隐藏/模糊、按场景切换敏感度 P0

D15 平台与系统（多租户 SaaS 底座）

详细需求见 05-identity-and-tenancy.md。

# 子域 内容 优先级
01 租户管理 创建家庭、邀请成员、配额、状态（试用/正常/停用/注销） P0
02 账号体系 注册、登录、找回、改密、二次验证、第三方登录 P0
03 权限模型 角色、权限点、数据范围、可见性规则 P0
04 通知中心 站内信 + 短信/邮件/微信模板消息、通知偏好 P0
05 审计日志 登录、敏感操作、数据访问、导出留痕 P0
06 数据导入导出 Excel/CSV 导入、全量导出、数据可携带 P0
07 备份与恢复 定时备份、回收站、误删恢复 P0

09 平台运营后台 租户列表、用量、公告、工单 P1
10 开放接口与集成 iCal 订阅、可穿戴同步、账单导入、IoT 扩展点 P2

附：域之间的交叉关系（避免重复录入）

数据 唯一归属 被谁引用
成员基础信息 D01 全部域的"归属成员"
