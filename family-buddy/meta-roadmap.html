二、各阶段定义与准出条件

① 调研 / 需求分析（进行中）

目标：把"想做什么"讲清楚，形成可评审、可排期、可验收的需求基线。

产出：

  • 01-requirements/ 全 9 篇文档
  • 00-meta/decisions/ 已发生决策的 ADR

准出条件（Exit Criteria）：

  • 15 个信息域全部过一遍，每个域明确 做 / 不做 / 远期
  • 每条 P0 需求有唯一 FR 编号、描述、验收要点
  • 09-open-questions.md 中的 Q 项全部关闭或明确降级为"接受不确定性"
  • 分期方案（08-scope-and-phasing.md）确认 v1 边界
  • 非功能需求中的安全与合规底线确认（PIPL 相关）

② 需求评审

目标：把需求定稿，冻结基线。 产出：需求基线版本号（如 req-v1.0）、变更流程约定。 准出：无未决策的 P0 项；所有"接受不确定性"项被显式记录。

③ 功能设计

目标：需求 → 功能模块、用例、页面、状态流转。 产出（docs/02-functional-design/）：模块划分、用例详述、状态机、页面清单与交互原型、权限矩阵。 准出：每个 P0 需求可映射到至少一个功能模块与页面。

④ 架构设计

目标：功能 → 系统结构、技术选型、数据模型、部署拓扑。 产出（docs/03-architecture/）：系统架构图、技术选型 ADR（含数据库/缓存/鉴权方案）、数据模型（ER + 表结构）、多租户隔离方案、部署与 CI/CD 方案、安全与合规方案、可观测性方案。 准出：关键技术风险有验证结论；选型可支撑 v1 全部 P0 需求。

⑤ 工程初始化

目标：把空壳跑起来。 产出：backend/ 可启动的 Spring Boot 工程 + frontend/ 可启动的 Vue 工程 + CI 流水线 + 本地一键启动。 准出：前后端本地联调可通过；CI 全绿。

⑥ 迭代开发

按 v1 范围拆分迭代（拆分方式在 ④ 之后定）。

四、明确不在本路线图中的事项（避免范围蔓延）

  • 移动端（App / 小程序）：远期，本路线图不排期
  • IoT 硬件直连（智能门锁、摄像头、手环）：v1 不做，仅预留数据模型扩展点
  • 商业化计费与支付：若确认要做，需单独立项，不在 v1 需求内
  • 社交/内容社区：非本项目目标
