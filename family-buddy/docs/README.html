项目：family-buddy（家庭伙伴） 阶段：调研 / 需求分析

在线阅读（HTML 版）

线上地址：https://<github-user>.github.io/open-sesame/family-buddy/index.html

（本地副本：打开 docs/site/index.html）

Markdown 是唯一事实来源，docs/site/ 是由它构建出的 HTML 站点。

站点形态：封面首页 + 每篇文档一页，共享 docs/site/assets/。

命名与结构约定

输出路径镜像源目录结构，文件名保持原样（只把 .md 换成 .html）：

README.md                                        → docs/site/README.html
docs/01-requirements/03-information-domains.md   → docs/site/docs/01-requirements/03-information-domains.html
  • 多个 README.md 靠目录区分，文档页一律不改名 —— 目录里文件一多，改过名的就认不出来了。
  • 封面页固定为 index.html：它由脚本生成、没有对应的源文件，按 Web 常规命名； 这样 …/family-buddy/ 这类目录 URL 能直接打开。
能力 位置
左侧导航（可折叠，分组可收展） 每页侧栏，桌面端折叠状态记忆在 localStorage
本页目录 + 滚动高亮 侧栏顶部 + 正文顶部
打印 / 导出 PDF 右上角「打印」按钮（打印样式已适配 A4，隐藏导航与侧栏）
返回封面首页 右下角「首页」按钮
本页查找 顶栏搜索框，或 ⌘K / Ctrl+K

重新构建

bash
<WorkBuddy venv>/bin/python docs/tools/build_site.py

构建是确定性的（不写入时间戳），同样的 Markdown 必然产出相同的 HTML —— 可用「重跑构建应无 diff」做自检。

改了目录结构（例如新增/重命名源文件）后，旧产物会成为遗留文件。构建会列出它们，加 --prune 可移入 .tmp/ 废纸篓：

bash
<WorkBuddy venv>/bin/python docs/tools/build_site.py --prune

发布到线上

见 00-meta/publish-pipeline.md（文档发布流程）：

bash
<WorkBuddy venv>/bin/python docs/tools/publish.py

docs/site/ 是构建产物。当前纳入版本库以便直接打开；若日后不希望提交生成物，把它加入 .gitignore 即可，Markdown 源不受影响。

docs/
├── 00-meta/              项目元信息：术语、路线图、决策记录、环境基线
├── 01-requirements/      需求分析（进行中）
├── 02-functional-design/ 功能设计（未启动）
├── 03-architecture/      架构设计（未启动）
└── 04-api/               接口契约（未启动）

文件命名约定：NN-kebab-case-name.md，序号表示阅读顺序。用英文文件名以保证跨平台、URL、CI 与静态站点生成的兼容性；标题与正文用中文。
