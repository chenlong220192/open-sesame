全部结论来自 2026-10-01 在本机的实际探测。标注规则见 docs/README.md。

一、仓库与远程

项 状态 证据（实测）
工作区 <项目根目录> pwd
分支 main，工作区干净 git status
远程 origin <私有仓库地址> git remote -v
提交历史 仅 1 个提交 8970ab0 init git log --oneline
GitHub SSH 认证 ✅ 可用，身份 <github-user> ssh -T git@github.com 返回 "successfully authenticated"
GitHub CLI gh 2.102.0 已安装，未登录 gh auth status → "not logged into any GitHub hosts"

gh 未登录不影响 push（SSH 已通）。仅在使用 gh 建 PR / 管理 Issue 时需要 gh auth login。

二、后端工具链

项 状态 证据（实测）
Maven ✅ 3.9.16，/opt/homebrew/bin/mvn mvn -v
Java 运行时（Maven 实际使用） ⚠️ JDK 27，/opt/homebrew/Cellar/openjdk/27 mvn -v → Java version: 27
JDK 25（本项目目标） ❌ 未安装 /opt/homebrew/Cellar/openjdk/ 下仅 27；brew info openjdk@25 → "Not installed"
Homebrew openjdk@25 可得性 ✅ 可安装，stable 25.0.4.1，keg-only brew info openjdk@25
JAVA_HOME ❌ 空 echo $JAVA_HOME
java / javac 命令 ❌ 不可用（macOS 占位符报 "Unable to locate a Java Runtime"） java -version
/Library/Java/JavaVirtualMachines/ ❌ 目录不存在（无系统级 JDK） ls 报 no matches
Gradle 未安装 which gradle 无结果

结论：目标栈 Java 25 尚未就绪，且当前 Maven 会自动挑到 JDK 27 —— 与"锁定 Java 25"的目标不一致。需显式安装 JDK 25 并把 JAVA_HOME 指向它，否则本地构建与 CI 会出现 JDK 版本漂移。

三、前端工具链

项 状态 证据（实测）
Node ✅ v22.22.2（WorkBuddy managed） node -v
npm 命令 ❌ 损坏 npm -v → Cannot find module '../lib/cli.js'
npm 包本体 ✅ 完好，版本 10.9.7 直接执行 lib/node_modules/npm/bin/npm-cli.js 成功
根因 bin/npm 是个 54 字节包装脚本，内容为 require('../lib/cli.js')(process)，而实际入口在 lib/node_modules/npm/bin/npm-cli.js —— 路径不匹配 对比两个路径，实测
pnpm / yarn ❌ 未安装 which pnpm yarn 无结果
corepack 存在（bin/corepack），未验证是否可用 —
nvm 已安装（Homebrew formula） brew list --formula

可行修复路径（3 选 1）：

  1. 把 bin/npm 内容改为 require('../lib/node_modules/npm/bin/npm-cli.js')(process) —— 实测目标路径可执行
  2. 用已有的 nvm 装一份独立 Node（推荐，隔离干净）
  3. corepack enable pnpm 走 pnpm —— 未验证

本目录是 WorkBuddy managed 运行时，重装/搬机会被重建，出现此类破损属预期，直接修即可。

四、其他

项 状态
Python 3.13.12（managed）—— 本项目当前无需
数据库 未安装（PostgreSQL / MySQL / Redis 均未探到）—— 架构阶段再定
Docker 未探测。公有云部署形态下需要，建议尽早确认

五、进入开发前的环境待办

# 事项 命令 阻塞级别
E1 设置 Git 全局身份 git config --global user.name "..." / user.email "..." 阻塞：未设置时首次 commit 会失败
E2 安装 JDK 25 brew install openjdk@25 阻塞：后端无法按目标版本构建
E3 设置 JAVA_HOME 指向 JDK 25 写入 ~/.zshenv（WorkBuddy 工具环境用 zsh -f，不读 .zshrc） 阻塞：同上，且影响 Maven 版本一致性
E4 修复 npm 或改用 pnpm/nvm 见上文第三节 阻塞：前端工程无法初始化
E5 （可选）gh auth login — 非阻塞
E6 确认 Docker 可用性 docker version 架构阶段前

E1/E3 涉及本机全局配置（~/.zshenv、git config）。是否现在处理，等你确认后再动手 —— 本次只做记录，未做任何修改。
