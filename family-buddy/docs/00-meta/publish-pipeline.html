文档发布流程 Publish Pipeline

把本项目的 HTML 文档站发布到共享的 GitHub Pages 仓库，使其可在任意设备上直接打开。 所有者将其命名为「文档发布流程」。

一、发布目标

项 值
宿主仓库 git@github.com:<github-user>/open-sesame.git（公开，多项目共用）
本项目子目录 family-buddy/
入口文件 family-buddy/index.html
线上地址 https://<github-user>.github.io/open-sesame/family-buddy/index.html
分支 main

封面页固定为 index.html，所以 …/family-buddy/ 这样的目录 URL 可直接打开；

该仓库是多项目共用的：本项目只拥有 family-buddy/ 一个子目录，不得改动仓库根或其它项目目录（同仓还有 health-buddy/）。

二、命名与结构约定（2026-10-02 定）

规则 说明
镜像源目录结构 发布树与仓库源树一一对应：docs/01-requirements/03-information-domains.md → family-buddy/docs/01-requirements/03-information-domains.html
文件名保持原样 只把扩展名从 .md 换成 .html，不做任何重命名
同名文件靠目录区分 多个 README.md 各自留在自己的目录里，不改名
一组文件用子目录组织 不靠文件名前缀制造伪层次
文档页一律不改名 目录里文件一多，改过名的就认不出来了。多个 README.md 靠目录区分
封面页固定为 index.html 它由脚本生成、无对应源文件，按 Web 常规命名；顺带让目录 URL 可用

三、脱敏（公开仓库的前置硬要求）

宿主仓库是公开的，而本项目的 Markdown 源里记录了只在本地/私有环境才有意义的信息。

本仓库保存原始文件，每次发布都必须走脱敏流程 —— 脱敏只作用于发布副本，源文档不改。

命中目标 替换为
私有仓库 SSH 地址 ＜私有仓库地址＞
私有仓库路径 ＜私有仓库＞
本机工作区绝对路径 ＜项目根目录＞
本机 venv 路径 ＜WorkBuddy venv＞
本机用户目录 ＜用户主目录＞
GitHub 用户名 ＜github-user＞

规则集中在 docs/tools/publish.py 顶部的 SANITIZE_RULES（按最长优先匹配）。 脚本每次都会打印每类规则的命中次数：命中数出现计划外类别，说明源文档新增了泄漏点，应补规则后重跑。

发布副本不含邮箱、真实姓名与任何凭据。唯一保留的 git@github.com 出现在通用命令 ssh -T git@github.com 中，非个人信息。

四、流程（六步，两段式：先暂存，再复制）

1. 重新构建文档站        docs/site/
2. 脱敏 → 写入暂存区      .tmp/publish-stage/     ← 人工核对点，含本次完整产物
3. 暂存区 → 目标目录      复制到 open-sesame/family-buddy/
4. 清理目标目录陈旧文件    移入 .tmp/trash/<时间戳>/from-open-sesame/
5. 提交                  一条 commit
6. 推送                  origin/main

两段式的意义：.tmp/publish-stage/ 是脱敏后的成品落地点，发布前后都可以直接打开核对； 同时它与目标仓库解耦，不会出现"写到一半目标已经被改"的状态。

覆盖语义：目标目录里不属于本次产出的文件会被移除，保证远端与本地构建结果严格一致。

陈旧文件与空目录一律丢进系统废纸篓（macOS 自带 /usr/bin/trash，实测可用）—— 不使用 rm / rmdir（所有者硬规则：删除走废纸篓，可恢复、误删代价低）。 仅当 trash 调用失败时，才退到本项目仓库的 .tmp/trash/<时间戳>/from-open-sesame/。 清理范围严格锁定在 family-buddy/ 内，不会越界影响同仓的其它项目。

四之二、临时区 .tmp/（仓库根）

所有临时文件、待删除文件、没有权限删除的文件都集中在 .tmp/，且绝不允许提交。

.tmp/
├── publish-stage/          发布暂存区
└── trash/<时间戳>/
    ├── site/                 构建遗留的旧产物
    ├── stale-stage/          暂存区自身的历史遗留
    └── from-open-sesame/     从目标仓库清理下来的
保护措施 说明
.gitignore 排除 git check-ignore .tmp/x 可验证
提交前拦截 发布脚本 git add -A 后检查暂存内容，若含 .tmp/ 下的文件则回滚暂存并中止
目标仓库隔离 发布脚本只往 open-sesame/family-buddy/ 写；.tmp/ 不再出现在目标仓库里

2026-10-02 曾发生一次：清理下来的 28 个废弃文件被放进 open-sesame/.tmp/， 随后被 git add -A 一并提交到公开仓库。内容为已脱敏的旧发布副本（无敏感信息）， 且 GitHub Pages 不服务 .tmp/（实测线上 404）。现已移出，并在该仓库根加了 .gitignore 防回归。

五、用法

bash
PY=<WorkBuddy venv>/bin/python

# 正式发布（构建 → 暂存 → 复制 → 清理 → 提交 → 推送）
$PY docs/tools/publish.py

# 只构建 + 写 .tmp/publish-stage/ 供人工核对，不碰目标仓库与 git
$PY docs/tools/publish.py --stage-only

# 试运行：构建 + 在临时目录试跑，报告会改动什么；不碰目标仓库与 git
$PY docs/tools/publish.py --dry-run

# 提交但不推送
$PY docs/tools/publish.py --no-push

发布后必须验证线上，不能凭 push 成功就下结论：

bash
$PY .workbuddy/skills/publish-docs/scripts/verify_published.py

完整的排查手册见 skill：.workbuddy/skills/publish-docs/SKILL.md（含实测踩坑与判据）。

六、已知注意事项

# 事项 说明
1 不能用状态码判断成败 Pages 的 CDN 会缓存 404，且重新部署有 30–120 秒延迟。必须比对内容
2 部署按文件滞后 实测发布 30 个文件后立刻校验，仍有 1 个文件返回旧内容，约 30 秒后才收敛
3 目录 URL 可用 封面页是 index.html，所以 …/family-buddy/ 直接可打开；也可用完整文件名
4 仓库启用了 Jekyll 已确认站点不含 {{ / {%，也无下划线开头的文件，不会被改写
5 多项目共用同一仓库 并发推送会 non-fast-forward；git pull --rebase 后重试，不要强推
6 发布不改变本项目源文件 本流程只写 open-sesame
