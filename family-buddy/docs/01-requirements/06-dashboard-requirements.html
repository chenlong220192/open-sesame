06 大屏 Dashboard 需求

你的诉求：可定制的大屏，用电视机打开。 这是本项目最具差异化的功能，也是技术风险最集中的功能（电视浏览器兼容性、常驻稳定性、隐私暴露）。

本文只写需求。技术方案（是否独立前端工程、用什么渲染、如何部署到电视）留到架构阶段。

一、使用场景

场景 描述 隐含需求
日常常驻 早起到睡前一直开着，家人随时瞥一眼 7×24 稳定、低资源占用、无内存泄漏
早晚高峰 出门前看天气/日程/待办 首屏信息优先级可配
晚间家庭 晚饭后看相册、家务轮值、留言 无操作也能自动轮播
有客来访 客厅有外人 敏感信息必须不可见
节日/纪念日 生日、结婚纪念日 可切换节日主题布局

二、终端与形态需求

ID 需求 优先级 说明
D-Q1 运行载体 P0 目标为电视浏览器打开一个 Web 页面（无需安装 App）
D-Q2 显示尺寸 P0 主要面向 1920×1080，兼容 4K；固定 16:9 布局
D-Q3 观看距离 P0 3 米外可读 → 主信息字号下限需明确（建议正文 ≥24px，关键数字更大；最终值在功能设计阶段以实机确认）
D-Q4 交互方式 P0 遥控器（方向键 + 确认）/ 触摸 / 无交互；不允许出现只能鼠标操作的控件
D-Q5 无输入即用 P0 遥控器打字极难 → 配置操作全部在手机/电脑端完成，大屏只负责展示
D-Q6 自动启动 P1 电视开机后自动进入大屏（Kiosk 模式）
D-Q7 免登录 P0 通过设备配对码接入，不输入账号密码

⚠️ 必须实测的前置风险（架构阶段第一件事）

风险 为什么是风险 现在必须做的事
电视浏览器内核版本未知 智能电视/机顶盒浏览器常停留在数年前的 Chromium 或自研内核，可能不支持新 ES 语法、CSS 新特性、WebGL 等 实测目标电视的浏览器 UA 与内核版本，据此决定构建目标与降级策略。在此之前不得假设"能跑现代 Vue 3 构建产物"
电视端可能无浏览器 / 无法输入网址 部分电视生态封闭 确认实际可用的访问路径；若必须用电视盒子/投屏，会影响方案
长时运行内存泄漏 电视浏览器长期不刷新容易 OOM 崩掉 需求上要求"可无人值守连续运行"，具体策略（定时自刷新等）架构阶段定

以上三项均为未验证项。01-vision-and-scope.md 假设 A2 依赖于此，若证伪需重评大屏方案。

三、功能需求

3.1 设备管理

ID 需求 优先级 验收要点
D-01 设备注册 P0 大屏打开后显示配对码；管理员在 Web 端输入并确认
D-02 设备命名与绑定 P0 设备可命名（客厅电视 / 卧室电视）；一个家庭可绑定多台
D-03 在线状态 P1 Web 端可见各设备最后在线时间
D-04 远程撤销 P0 撤销后设备立即无法拉取数据
D-05 无写权限 P0 设备令牌不得具备任何写操作能力

3.2 布局与定制（核心诉求）

ID 需求 优先级 验收要点
D-10 栅格布局 P0 基于栅格的卡片排布；卡片可跨行列
D-11 卡片增删 P0 从卡片库拖入 / 移除
D-12 卡片拖拽换位 P0 拖拽后布局持久化
D-13 卡片缩放 P0 支持至少 3 档尺寸（小/中/大）
D-14 布局实时生效 P0 保存后大屏无需刷新即生效（或最多延迟一个刷新周期）
D-15 多套布局 P0 可保存并命名多套布局，可指定默认布局
D-16 卡片级配置 P0 每张卡片可配参数（如日历卡片选哪些成员、相册选哪个相簿、健康卡片选哪些指标）
D-17 布局模板 P1 提供几套预置模板（极简 / 信息密集 / 相册主导）供快速起步
D-18 预览 P1 编辑时可预览实际效果
D-19 撤销 P2 编辑历史可回退

需求约束：编辑操作全部在管理端（手机/电脑）完成，大屏端只读。理由：遥控器无法完成拖拽配置。

3.3 卡片库

P0 必备卡片（v1）

卡片 数据来源 关键展示要素
时钟 / 日期 本地 大字号时间、日期、星期、农历
天气 外部天气服务 当前温度、天气、今日高低温、未来几天（需接入第三方 API，见 Q-012）
家庭日历 D07 今日/本周事件，含参与人
待办清单 D07 未完成待办，按负责人分组
生日与纪念日倒计时 D07 最近 N 个纪念日 + 剩余天数
家庭相册 D13 自动轮播照片
纪念日/节日主题 D07 节日当天自动切换氛围样式
留言板 D07 家庭成员互相留言
家务轮值 D07 本周/今日谁负责什么
快捷信息 D11 近期到期提醒（证件/账单/车检）

P1 卡片

卡片 数据来源 备注
健康概览 D03 默认脱敏（仅显示趋势或模糊数值）
财务概览 D04 默认隐藏，仅在特定场景开启
家庭相册 / 成长记录 D08 儿童成长里程碑
快递 / 物流 外部 需第三方接口
倒计时（自定义） D07 如考试、旅行
待领取 / 采购清单 D06 家庭库存补货

P2 卡片：股市行情、新闻、用电量、IoT（门锁/摄像头状态）、运动步数榜

需求约束：任何需要外部数据源的卡片，必须能优雅降级 —— 接口不可用时显示占位而非报错或白屏。

3.4 展示与运行策略

ID 需求 优先级 验收要点
D-30 自动刷新 P0 可配置刷新周期（如 5/15/60 分钟）；不同卡片可不同
D-31 增量刷新 P1 只更新变化的卡片，避免整页闪烁
D-32 失败隔离 P0 单卡片加载失败只影响该卡片，其余正常；失败卡片显示重试提示
D-33 断网表现 P0 断网时展示最后一次成功数据 + 离线提示；不白屏
D-34 防烧屏 P0 长时间静态元素（时钟、边框）需支持位置微移或透明度周期变化
D-35 夜间模式 P1 按时间自动降低亮度或熄屏（电视端可能需系统配合）
D-36 相册轮播 P1 照片按时长自动切换，避免固定图停留过久
D-37 长时稳定性 P0 连续运行 7 天不崩、不显著卡顿（验收需实测）
D-38 资源占用 P1 低端电视上不明显掉帧；避免高频动画

3.5 隐私脱敏（需求级别最高）

客厅大屏是物理公开的。这是本项目最容易被忽视、也最容易造成真实伤害的地方（例如把体检异常、账户余额、工资条投在客厅）。

ID 需求 优先级 验收要点
D-40 敏感卡片默认关闭 P0 财务类、健康类、证件类卡片默认不添加，需管理员显式开启
D-41 脱敏模式 P0 金融/健康数值可配置为：隐藏 / 模糊 / 区间化（如"正常范围"）/ 完整显示
D-42 场景切换 P1 "日常 / 节日 / 来客"场景可绑定不同的脱敏级别，一键切换
D-43 敏感内容不入相册轮播 P0 相册卡片不展示被标记为敏感的照片
D-44 未授权设备不可访问 P0 配对码未确认前，设备无法获取任何数据
D-45 单卡片锁定 P1 可对单张卡片设置"仅管理员可见"（如账单卡片在无管理员在场时隐藏）

四、体验要求

# 要求 判据
1 一眼可读 3 米外能看清核心信息；层级分明（时间/日期 > 日程 > 次要信息）
2 信息密度可控 至少支持"极简（3-5 张卡）"到"密集（10+ 张卡）"两档
3 视觉统一 同一布局内颜色/字号/间距统一；不同卡片不打架
4 无操作可用 全流程不需要遥控器点击即可长期运行
5 主题可配 支持浅色/深色/节日主题；深色为默认（客厅夜间观感更好，且更省电）

五、明确不做（v1 范围外）

不做 理由
在大屏上录入/编辑数据 遥控器无法完成；且破坏"只读展示"的安全前提
大屏端账号密码登录 客厅场景不适用，且泄漏风险高
大屏体感/语音交互 依赖特定硬件，范围外
多屏拼接/超宽屏 需求未出现，先不做
视频播放/直播 非本项目目标

六、待确认

# 问题 编号
1 目标电视的具体型号与浏览器内核（架构阶段第一优先级） Q-004
2 电视是否可安装第三方浏览器 / 是否用电视盒子 Q-004
3 是否需要自动开机启动（Kiosk） Q-004
4 天气/快递等外部数据源用哪家、是否付费 Q-012
5 相册照片从哪来（手动上传 / 手机相册同步 / 云盘） Q-013
