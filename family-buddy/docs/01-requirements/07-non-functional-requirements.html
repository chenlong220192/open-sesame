07 非功能需求 Non-Functional Requirements

源文件docs/01-requirements/07-non-functional-requirements.md 项目family-buddy 阶段调研 · 需求分析

编号：NFR-{类别}-{序号}。类别：PERF 性能 / AVAIL 可用性 / SEC 安全 / COMP 合规 / MAINT 可维护 / COMPAT 兼容 / OBS 可观测 / COST 成本。

说明：由于是单人开发 + 业余时间 + 早期个位数家庭，本文的性能与可用性指标刻意定得保守 —— 目标是"够用且不给自己挖坑"，不是"对标企业级"。真正需要硬性满足的是安全与数据正确性。

一、性能 NFR-PERF

ID 需求 指标 优先级 说明
NFR-PERF-01 页面首屏 管理端主要页面 ≤2s（家用宽带、缓存命中） P1 早期家庭少，不做极端优化
NFR-PERF-02 接口响应 常规查询 P95 ≤500ms P1 数据量级假设见 A3（每年数百条/域）
NFR-PERF-03 大屏首屏 大屏页面 ≤3s 出现可用内容 P0 电视性能弱，需优先保证
NFR-PERF-04 大屏数据刷新 单次刷新 ≤2s P0 超时需降级为展示缓存数据
NFR-PERF-05 大屏常驻 连续 7 天不发生崩溃或明显卡顿 P0 需实测验收
NFR-PERF-06 并发规模 支撑 ≥50 个家庭、≥500 账号的并发访问 P2 早期远超需求，作为不主动破坏的上限
NFR-PERF-07 附件上传 ≤20MB 文件上传成功率 ≥99% P1 大文件需分片或断点续传则另议

不做的事：早期不做压测、不做缓存调优、不做 CDN。这些在真实出现性能问题前都是浪费。

二、可用性 NFR-AVAIL

ID 需求 指标 优先级
NFR-AVAIL-01 服务可用性 目标 99%（允许每月约 7 小时不可用） P1
NFR-AVAIL-02 数据不丢 任何情况下不得丢失已提交数据 P0
NFR-AVAIL-03 备份 数据库每日自动备份，保留 ≥30 天 P0
NFR-AVAIL-04 恢复演练 必须实际演练过至少一次完整恢复 P0
NFR-AVAIL-05 大屏容错 后端不可用时不白屏，展示最后一次缓存数据并提示离线 P0
NFR-AVAIL-06 优雅降级 外部依赖（天气等）不可用时仅对应卡片降级 P0
NFR-AVAIL-07 误删恢复 删除数据可从回收站恢复 ≥30 天 P1

NFR-AVAIL-04 单独列出，因为"有备份但没演练"是典型的假安全。未演练的恢复方案等同于没有恢复方案。

三、安全 NFR-SEC（硬性要求，不可协商）

来源：ADR-0003（公有云部署）+ ADR-0002（多租户 SaaS）。

ID 需求 优先级 判据
NFR-SEC-01 全站 HTTPS P0 禁止明文 HTTP 承载凭据；HSTS 开启
NFR-SEC-02 认证不自研 P0 使用成熟框架实现，禁止手写加密/会话/令牌逻辑
NFR-SEC-03 密码存储 P0 使用标准自适应哈希（如 bcrypt/argon2），加盐；禁止明文/MD5/SHA1
NFR-SEC-04 授权后端校验 P0 前端隐藏不等于后端拒绝；每个接口独立校验权限
NFR-SEC-05 租户隔离 P0 见 05-identity-and-tenancy.md T1–T6
NFR-SEC-06 中间件不暴露 P0 数据库/缓存/消息不得监听公网；仅反向代理 443 对外
NFR-SEC-07 限流 P0 登录/注册/验证码/找回密码接口必须限流与失败锁定
NFR-SEC-08 敏感字段加密 P0 证件号、卡号等字段级加密，密钥与数据分离
NFR-SEC-09 审计日志 P0 登录、权限变更、敏感数据访问与导出必须留痕
NFR-SEC-10 注入与 XSS 防护 P0 参数化查询；输出转义；附件类型与内容校验
NFR-SEC-11 附件访问控制 P0 附件不可通过猜测直链访问，必须鉴权
NFR-SEC-12 依赖漏洞 P1 定期检查依赖漏洞（可自动化）
NFR-SEC-13 密钥管理 P0 密钥不得提交仓库；.gitignore 已覆盖，需落实到部署
NFR-SEC-14 越权测试 P0 必须有自动化跨租户越权测试用例
NFR-SEC-15 管理端防护 P1 平台运营后台建议限制访问来源或强制 2FA

四、合规 NFR-COMP

见 05-identity-and-tenancy.md 第六节。核心条目：告知同意、最小必要、未成年人保护、查阅更正、数据可携带、删除权与注销、敏感字段加密、访问审计。

诚实声明：需求清单 ≠ 合规结论。对外提供服务前需专门评审。

五、可维护性 NFR-MAINT

ID 需求 优先级 说明
NFR-MAINT-01 单人可维护 P0 架构复杂度必须控制在单人业余可维护范围内；拒绝过度设计
NFR-MAINT-02 一键本地启动 P0 新环境从 0 到跑起来 ≤30 分钟，有文档
NFR-MAINT-03 前后端独立构建 P0 各自可单独构建与部署（ADR-0001）
NFR-MAINT-04 数据库变更可追溯 P0 使用版本化迁移工具，禁止手工改生产表
NFR-MAINT-05 新增信息域成本可控 P0 新增一个域的增量成本应主要为"配置 + 简单 CRUD"，不需改核心
NFR-MAINT-06 代码规范自动化 P1 后端/前端各有格式化与静态检查，可一键执行
NFR-MAINT-07 自动化测试 P1 关键路径（认证、权限、租户隔离、记账）必须有测试；不追求覆盖率数字
NFR-MAINT-08 文档与代码同步 P1 需求编号（FR）需能追溯到实现
NFR-MAINT-09 版本锁定 P0 依赖版本显式锁定；JDK 版本显式锁定（见 ADR-0004）

六、兼容性 NFR-COMPAT

ID 需求 优先级 说明
NFR-COMPAT-01 管理端浏览器 P0 Chrome / Edge / Safari 近两年版本；移动端浏览器必须可用（家人主要用手机）
NFR-COMPAT-02 移动端适配 P0 管理端为响应式，手机端可用（不是 App，是 Web）
NFR-COMPAT-03 大屏浏览器 P0 以实测的目标电视内核为准；若内核过旧需构建期降级 —— 实测前不得假定可运行
NFR-COMPAT-04 分辨率 P0 大屏 1920×1080 为主，兼容 4K；管理端 ≥360px 宽
NFR-COMPAT-05 网络 P1 弱网（4G）下基本可用；大屏断网可降级展示

七、可观测性 NFR-OBS

ID 需求 优先级 说明
NFR-OBS-01 结构化日志 P0 能按请求追踪；日志不记录敏感明文
NFR-OBS-02 错误可定位 P0 线上报错能拿到足够上下文定位（单人运维的生命线）
NFR-OBS-03 健康检查 P0 提供健康检查端点供反向代理/监控使用
NFR-OBS-04 告警 P1 服务不可用、备份失败、磁盘将满时能通知到你
NFR-OBS-05 大屏设备状态 P1 能看到各设备最后心跳时间

八、成本 NFR-COST

ID 需求 优先级 说明
NFR-COST-01 月度成本上限 P1 待你设定金额上限（见 Q-014）；早期应尽可能低
NFR-COST-02 存储成本可控 P1 相册/附件需有配额与生命周期策略，避免无限增长
NFR-COST-03 可降级 P2 免费额度耗尽或涨价时有降级预案

九、国际化与本地化

ID 需求 优先级
NFR-I18N-01 中文为主 P0（界面全中文）
NFR-I18N-02 农历支持 P0（D07 生日与纪念日依赖）
NFR-I18N-03 多时区 P2
NFR-I18N-04 多语言 P2

十、优先级汇总（哪些是"绝不能妥协"的）

类别 是否可妥协
安全（NFR-SEC-01~14） ❌ 不可妥协（因公有云 + 敏感数据）
数据正确性与不丢失 ❌ 不可妥协
合规最低要求 ❌ 不可妥协
大屏长时稳定性 ⚠️ 可降级（可通过定时刷新规避，但需实测确认）
性能指标 ✅ 可妥协（早期用户少）
可用性 99% ✅ 可妥协（个人项目，短暂不可用可接受）
兼容性范围 ✅ 可妥协（限定浏览器与设备）
成本 ⚠️ 需你设上限
