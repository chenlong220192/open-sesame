ADR-0003 部署形态定为公有云服务器

源文件docs/00-meta/decisions/ADR-0003-cloud-deployment.md 项目family-buddy 阶段调研 · 需求分析

  • 后果

  • 未决项
  • 状态：已接受
  • 日期：2026-10-01
  • 决策者：项目所有者
  • 影响范围：安全需求、可用性需求、成本、CI/CD、合规义务

背景

部署形态直接决定安全需求强度。三种典型形态：家庭内网自建（NAS/迷你主机）、内网自建 + 远程接入、公有云服务器。

项目所有者选择公有云服务器。

决策

部署在公有云服务器上，服务多个家庭（与 ADR-0002 一致）。因此系统处于公网可达环境，所有接口默认视为"可被任何人扫描和攻击"。

备选方案与取舍

方案 安全强度要求 外网访问 成本 采纳
家庭内网自建 低（物理隔离即主要防线） 需额外打通 一次性硬件 ❌
内网 + Tailscale/frp 中 依赖叠加网络 低 ❌
公有云服务器 高 天然支持 持续月费 ✅

后果

该决策强制引入以下非功能需求（详见 01-requirements/07-non-functional-requirements.md）

  1. 全站 HTTPS，禁止明文 HTTP 承载任何凭据。
  2. 认证与授权不可自研：使用成熟方案（Spring Security 体系），禁止手写加密/会话/令牌逻辑。
  3. 公网暴露面最小化：数据库、缓存、消息等中间件不得监听公网；仅反向代理 443 端口对外。
  4. 限流与防暴力破解：登录、注册、验证码、Otp 接口必须有速率限制与失败锁定。
  5. 审计日志：登录、敏感数据访问、导出操作必须留痕且不可被普通管理员删除。
  6. 备份与恢复：数据库需定时备份 + 异地/异构存储，且必须实际演练过一次恢复（仅备份不演练等于没有备份）。
  7. PIPL 合规义务：作为个人信息处理者，需具备告知同意、最小必要收集、删除权响应、数据泄露应急等能力。

成本与风险

  • 成本：持续云费用 + 运维时间。早期流量极小，建议先用最低配并保留升级路径，具体规格留到架构阶段。
  • 风险：由于是个人项目 + 公网 + 家庭敏感数据（健康、财务、证件），一旦被入侵，后果不可逆。
  • 缓解：上述 7 条为硬性要求。若某条因成本无法满足，需记录为显式已知风险，不得默认忽略。

未决项

  • 云厂商与区域：未定（架构阶段）
  • 是否采用容器化部署：未定，但 Docker 可用性尚未探测（见 dev-environment.md E6）
