文档发布流程 Publish Pipeline

把本项目的 HTML 文档站发布到共享的 GitHub Pages 仓库，使其可在任意设备上直接打开。 所有者将其命名为「文档发布流程」。

一、发布目标

项 值
宿主仓库 git@github.com:<github-user>/open-sesame.git（公开，多项目共用）
本项目子目录 family-buddy/
线上地址 https://<github-user>.github.io/open-sesame/family-buddy/
分支 main

已实测（2026-10-01）：首页、index.html、assets/docs.css、assets/docs.js、内页 req-03.html 均返回 200，内容标记齐全。

该仓库是多项目共用的：本项目只拥有 family-buddy/ 一个子目录，不得改动仓库根目录的其它内容。

二、流程（五步，每次执行都是幂等的全量覆盖）

1. 重新构建文档站        docs/site/
2. 脱敏                  把只对本地/私有环境有意义的字符串替换为占位符
3. 全量覆盖写入          目标仓库的 family-buddy/ 子目录
4. 提交                  一条 commit
5. 推送                  origin/main

覆盖语义：目标目录里不属于本次产出的文件会被删除，保证远端与本地构建结果严格一致，不会残留上次发布的历史页面。

三、用法

bash
PY=<WorkBuddy venv>/bin/python

# 正式发布（构建 → 脱敏 → 覆盖 → 提交 → 推送）
$PY docs/tools/publish.py

# 试运行：只构建 + 复制 + 报告，不碰 git
$PY docs/tools/publish.py --dry-run

# 提交但不推送（先本地看一眼）
$PY docs/tools/publish.py --no-push

脚本位置：docs/tools/publish.py。目标仓库与脱敏规则都是脚本顶部的常量。

四、脱敏（为什么必须有这一步）

宿主仓库是公开的，而本项目的 Markdown 源里记录了只在本地/私有环境才有意义的信息。 Markdown 源始终保留真实信息（它是私有仓库里的事实记录），脱敏只作用于「要公开发布的那一份」。

当前规则（按最长优先匹配）：

命中目标 替换为
私有仓库 SSH 地址 ＜私有仓库地址＞
私有仓库路径 ＜私有仓库＞
本机工作区绝对路径 ＜项目根目录＞
本机 venv 路径 ＜WorkBuddy venv＞
本机用户目录 ＜用户主目录＞
GitHub 用户名 ＜github-user＞

脚本每次都会打印每类规则的命中次数。若命中数出现计划外的类别，说明源文档里新增了泄漏点，应补充规则。

发布副本不包含：邮箱、真实姓名、任何凭据。 唯一保留的 git@github.com 出现在通用命令 ssh -T git@github.com 中，非个人信息。

五、已知注意事项

# 事项 说明
1 Pages 的 CDN 会缓存 404 首次发布后，之前探测过的路径可能仍然返回 404（实测约 30–60 秒）。用带查询参数的 URL（?v=<时间戳>）穿透缓存即可，不必反复重推
2 仓库启用了 Jekyll 已确认站点内容不含 {{ / {%，也没有下划线开头的文件，故 Jekyll 不会改写内容。若将来新增这类文件，需在仓库根加 .nojekyll
3 目录 URL 依赖 index.html .../family-buddy/ 能直接打开，是因为构建产物里有 index.html
4 多项目共用同一仓库 同一时刻的并发推送可能冲突；推送失败时先 git pull --rebase 再重试
5 发布不改变私有仓库 本流程只写 open-sesame，不修改本项目仓库的任何文件
