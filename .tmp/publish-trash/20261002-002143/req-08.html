08 分期与范围 Release Phasing

本文解决当前最大的风险：需求池里 P0 条目约 55 条，而开发资源是"一个人 + 业余时间"。 结论：v1 必须再砍。 本文给出砍的判据（比具体清单更重要）与建议边界。

一、砍需求的五条判据

按优先级从高到低应用：

序 判据 含义 反例（该被砍/延后）
1 是否有"到点会痛"的价值 到期提醒类（证件、还款、保险、车检、保修、用药）优先级最高 —— 不做会实际吃亏 投资持仓分析（不做也不会出事）
2 是否已被现有工具勉强覆盖 能被 Excel/微信勉强替代的，可以延后 记账（有了系统更好，但现在也能记）
3 是否依赖未做的域 依赖者必须排在依赖项之后 车辆保险到期 ← 依赖 D05
4 服务的人数 × 频次 只有一个人用、一年用两次的，延后 家谱、旅行记录
5 录入成本是否高于收益 需要大量手工录入才能体现价值的功能，砍 收支明细逐笔记账（若家人不配合）

补充原则：每个纳入的域 v1 只做最小可用形态 = 手工录入 + 列表 + 详情 + 附件。不做批量自动化、不做智能分析、不做图表美化。

二、建议的 v1 边界

2.1 v1 必做：底座（不可省）

模块 范围 理由
D15 账号与租户 注册/登录/家庭创建/邀请成员/密码找回 没有它就没有系统
D15 权限 4 类内置角色 + 域×操作的权限点 + 数据范围 + 成员间可见性 ADR-0002 硬约束，后补成本极高
D15 隔离与审计 租户隔离机制 + 越权测试 + 审计日志 安全底线
D15 备份与导出 定时备份 + 全量导出 数据可带走是承诺
D01 家庭与成员 成员 CRUD（含无账号成员）、关系、角色分配、基础档案 所有域的挂载点
D13 附件（仅子域 01） 上传/关联/预览/下载 所有域的基础设施

2.2 v1 必做：通用能力

模块 范围
通用列表 分页/排序/筛选/导出
通用导入 Excel/CSV 模板导入（至少支持记账与成员）
统一提醒引擎（FR-D07-07） 所有到期类需求的唯一实现
时间序列展示 数值记录的趋势图

2.3 v1 必做：首批业务域（建议 3 个）

域 v1 做的子域 砍掉的子域
D03 健康与医疗 01 体检、02 指标记录、03 指标字典、05 用药、08 过敏病史、09 就诊 慢病随访、疫苗、运动睡眠、专科、女性健康
D04 财务与资产 01 账户、02 记账、03 分类、04 查询统计、05 批量导入、08 负债月供、09 账单订阅 预算、净值快照、保险、投资、财务目标
D07 日历与日程 01 共享日历、02 个人日程、03 纪念日（含农历）、04 待办、07 提醒中心 家务轮值、家庭会议、iCal 导出
D11 生活事务 仅 01 证件到期管理 会员订阅（并入 D04-09）、宠物、签证、日记
D02 工作与职业 01 任职信息、02 薪酬结构 社保、假勤、职业发展、履历、副业、求职

D02 只做两个子域，因为它对"家庭共同决策"的贡献有限，但个人信息完整度需要它。

2.4 v1 必做：大屏最小版

做 不做
设备配对与撤销 场景切换
栅格布局 + 拖拽 + 增删 + 缩放（P0 的 D-10~D-16） 编辑历史回退
4 张卡片：时钟、家庭日历、生日纪念日倒计时、待办清单 天气（依赖外部 API，见 Q-012）
自动刷新 + 失败隔离 + 断网降级 相册轮播（依赖照片来源，见 Q-013）
防烧屏 健康/财务卡片（脱敏方案未定，先不做）

大屏 v1 刻意只做 4 张卡：先证明"能在你家电视上稳定跑起来"，再谈丰富度。这是风险前置的必要做法（电视兼容性尚未验证，见 Q-004）。

2.5 v1 明确不做

不做 去向
D05 房产与车辆（含车检/保险到期提醒） v1.1（其实价值高，是第一批补充）
D06 家居与设备（含保修、药箱、固定费用） v1.1
D08 子女与教育（含课时余额） v1.1
D09 长辈照护 v1.1
D10 关系与人情（含还礼提醒） v1.1（价值高，可提前）
D12 旅行与出行 P2
D13-02 重要信息保管 待 Q-010 决策
移动端 远期
第三方登录、2FA v1.1
平台运营后台 v1.1
外部通知渠道（短信/微信） v1.1（短信有实名与费用成本，见 Q-017）
自动化账单导入、OCR 全量结构化 P2

三、里程碑

里程碑 内容 达成判据
M0 需求冻结 本文 + 09 中 P0 相关 Q 项全部关闭 无未决 P0 问题
M1 底座可跑 注册 → 建家庭 → 邀请成员 → 分配角色 → 登录 两个账号在同一个家庭内互不越权
M2 单域打通 D03 健康完整走通（录入 → 列表 → 趋势 → 附件） 自家能真实使用
M3 多域 + 提醒 D02/D04/D07/D11 上线，提醒中心生效 到期项能收到提醒
M4 大屏可用 大屏在真实电视上连续运行 7 天 NFR-PERF-05 实测通过
M5 多租户验证 第二个家庭自主注册并完整使用 01-vision-and-scope.md 的 M3 标准
M6 外部分发 D05/D06/D08/D09/D10 补齐 按需排期

四、范围变更规则

规则 说明
R1 新增需求一律先进需求池（04 文档），不直接进当前迭代
R2 进入当前迭代的需求必须是 P0，且不能挤掉既有 P0
R3 若必须插入，需等价移除一条同级需求（等量交换）
R4 每条需求变更需标注日期与原因；需求基线版本号在 M0 冻结后启用
R5 任何降低安全或隔离要求的变更，一律拒绝

R3 与 R5 是最重要的两条。R3 防止范围悄悄膨胀，R5 防止安全被"先这样，以后补"侵蚀。
